# iStart architecture

## Status and constraints

iStart is a single C#/.NET 10 WPF desktop project with no additional NuGet dependencies. Windows Forms supplies monitor information and suspend capability; no NotifyIcon or tray menu is created. Inno Setup 7.1.0 produces a Chinese, per-user, self-contained installer.

The target is Windows 10/11 x64. Known Windows 10 builds 19041–19045 and Windows 11 builds 22000/22621/22631/26100/26200/26300 may opt into capability-checked trials; other builds retain native Start. Only build 26200 has basic hardware integration evidence. Build 26300 has read-only button discovery and fixture evidence, not live input acceptance. See [P0 validation](docs/P0_VALIDATION.md).

## Development workspace

The local checkout and development output are consolidated under `E:\workspace\istart`: `.istart-tools/` contains the SDK/compiler, `.istart-testlab/` contains VM disks, images and private test materials, and `artifacts/design-previews/` contains interactive design previews. These directories are Git-ignored and never enter public release assets. Compatibility junctions preserve old registered-tool/VM paths and preview links; they do not duplicate storage. This layout does not relocate the installed application or its user configuration.

Local release retention is independent of application data and remote releases: keep five published installer/checksum/manifest sets in `artifacts/releases/<version>/`; remove obsolete or duplicate generated packages only after verification. Developer tools, VM baselines, configuration backups and required diagnostic evidence remain protected.

## Module boundaries

| Module | Responsibilities and boundaries |
| --- | --- |
| MainWindow / Refresh / Editing / Shell / Websites / Computer | Five fixed views, retained menu state, deferred background refresh, search, icon/list display, adding and hiding items, activity ordering, Settings and placement; ordinary-user execution |
| LibraryStore | Items, legacy categories, preferences, and recent records; copy before mutation, write a temporary file, atomically replace, retain one backup; a failed save does not replace in-memory state |
| Localization / Strings.en.json | Central product text and English translations; current-user Windows display language; immediate WPF binding updates; stable navigation and shortcut identifiers |
| SoftwareDiscovery / ShellShortcut | Asynchronous discovery of user/common Start-menu `.lnk` files; Unicode IShellLinkW/IPersistFile parsing; deduplicated valid EXE targets; installer, maintenance, and invalid-entry filtering |
| FreeCadDocuments | Bounded, read-only FreeCAD recent-file configuration reader; local files only, merged through RecentDocuments and the existing external-history preference |
| ShellIcon / IconReader / ShellIconConverter | Immediate embedded placeholder, two background STA readers, bounded queue/cache, frozen Shell images, and UI-dispatcher updates; generic UNC icons avoid remote icon reads |
| StartMenuAdapter / ShellCompatibility / WinInput | Build policy, UIAutomation/native Start-child discovery, standalone Win and Start-button low-level hooks, combination passthrough, and marked native injection to prevent recursion |
| NativeMenu | Marked SendInput Ctrl+Esc requests for temporary native Start |
| UpdateService / GitHubUpdater / UpdateWindow | Shared update state, online checks and scheduling, verified downloads/install launch, badges, release notes, and user preferences |
| SystemActions | Capability/policy checks for lock, sign-out, switch user, sleep, hibernate, shutdown, and restart; fixed arguments without `/f` |
| Program / InstanceChannel / App | Pre-WPF resident handoff, current-SID mutex ownership and show/enable/exit signals, bounded graceful-exit waits, full-startup race recovery, background/diagnostic modes, and isolated UI tests |
| installer / scripts / CI | Chinese wizard and real file progress, graceful exit before upgrades, uninstall and checksums; separate QA AppId; no server deployment |

The process does not inject into Explorer, modify system binaries, replace authentication, install a service, or install a driver. Temporary native Start access and switching the default to native mode are separate operations.

Activity reads in preview.25: MainWindow reads AppSwitched before discovery and supplies that same snapshot to ranking. SoftwareDiscovery supplements shortcuts/packages from at most 2,048 positive usage records, adding at most 128 valid new local EXEs, excludes network paths, installers and common helper processes, and deduplicates by target. Existing shortcut arguments and working directories take precedence. It does not enumerate whole drives. FreeCadDocuments reads `%APPDATA%/FreeCAD/user.cfg` and up to eight immediate `v*` profiles (at most 4 MiB per config), with shared read access, DTD/external resolution disabled, and independent config failure handling. Only `Root/BaseApp/Preferences/RecentFiles` numeric `MRU` text entries are used, at most 100 per config. MRU order is preserved; config modification time is approximate merge evidence, not a precise per-file opening time. The existing 100-file merge, local-file filters, and ShowWindowsRecentDocuments setting apply. A missing Windows Recent folder no longer prevents application-private reads. Source histories remain unchanged and external results remain in memory.

### Presentation and focus

Program is the entry point. It opens the existing current-SID channel before creating Application or loading resources; a successful show/enable/exit handoff never initializes WPF. Missing, unowned, or abandoned mutexes fall through to normal startup, preserving crash recovery. App acquires mutex ownership rather than treating an existing name as a live process, covering shutdown races. The foreground grant still targets the existing same-path, same-session app. Show signals coalesce into one pending Input-priority dispatcher request. Diagnostic arguments bypass this shortcut; the QA-only GUID namespace cannot signal the user's production channel and fails closed if the wrong entry point is selected.

The local HwndSource hook handles SC_RESTORE from the taskbar through ShowMenu, restoring normal dimensions and bottom-left placement from retained data. Presentation generations cancel a restore queued before a later hide/show. These local window-message hooks and hide cleanup also apply when global Shell integration is disabled; tests can exercise restoration without global input hooks. Closed/exiting windows ignore late show requests. Entry-list double-click bindings are unchanged.

Resident menu reopening retains the same visual tree, items source, query, selection, and scroll position. ShowMenu performs placement, visibility, and focus, then schedules a 200 ms ContextIdle timer; it does not invoke activity readers, target validation, or ranking. Loaded no longer starts software discovery, and folder-size changes schedule a deferred refresh instead of rebuilding during opening layout. Hiding cancels the timer and invalidates pending presentation results. The cache is process memory only; it does not persist external history or restore content across process exits.

MainWindow.Refresh coalesces visible refresh requests into one pipeline. Source reads update memory without rendering. Once they complete, mutable settings and source arrays are copied on the dispatcher; worker closures perform existence checks, shortcut classification, history merging, and ranking without touching WPF or LibraryStore. Results apply at ContextIdle only if the presentation/query revision is still current and visible. Slow or failed reads retain displayed content. Unfinished file/folder/browser reads, like software reads, remain shared after a waiter times out. Explicit search/edit actions still update immediately; they invalidate older background results.

Rows are compared by target, title, category, and real pinned IDs before replacing ItemsSource; regenerated suggestion IDs alone do not recreate controls. Changed lists retain selection by target and the current scroll offset. My Computer also reuses unchanged cards, preserving expansion and scroll state. Interactive software searches retain the existing classification cache; background builders use their own classification instance to avoid sharing mutable dictionaries across threads.

The preview.25 activity audit adds a shared bounded reader collector in RecentDocuments: recoverable link/Jump List/application errors are isolated, and a folder-reader failure does not discard completed document reads. MainWindow retains a partial-failure count in memory and displays a translated warning. Cancellation and the five-second wait remain unchanged. Preview.26 shares a running software-discovery request, reuses successful results for 30 seconds, and retains an unfinished native read after a waiter times out instead of spawning overlapping reads. Application classification is cached between searches and invalidated after discovery. FrequentFolders filters search before taking the result limit and canonicalizes duplicate pinned-folder spellings in memory. No configuration schema or external-history writes were added.

ShowMenu no longer depends on `adapter.Enabled` for topmost/focus behavior: desktop icons and repeated launches use the same path. Hiding clears Topmost; deactivation hides the menu. Focus retries are bounded to four attempts, 60 ms apart, with a presentation generation preventing a delayed retry from reopening an old window. Search focus uses Input priority so background loading does not delay it.

A repeated launch calls AllowSetForegroundWindow only for an existing iStart process in the same session and at the same path, then sends the show signal. It does not grant foreground access to arbitrary processes. Initial integration still requires Enable integration or the Settings switch; a chosen native mode is not automatically replaced.

ShowMenu restores Normal state, enables ShowActivated, raises the window temporarily, requests SetForegroundWindow, and focuses search. Every user-triggered opening stays temporarily topmost until hidden, regardless of integration mode. Synchronous Deactivated events during presentation must not hide it prematurely. Background startup hides immediately after the first Show rather than at the end of asynchronous initialization.

MainWindow uses Manual startup placement. Initial visible startup and repeated show signals both call ShowMenu; keyboard/repeated opens capture the foreground monitor before showing or activating the menu. PlaceMenu runs independently of adapter.Enabled before Show and again afterward to account for a display-DPI change. MenuPlacement clamps dimensions to the physical working area and anchors to its left/bottom edges with at most eight pixels of spacing; Start-button coordinates and a prior dragged position do not set the anchor. SetWindowPos only positions the window and does not activate it. ShowInBackground uses the same placement, disables activation, then synchronously hides. This changes launcher placement without expanding the integration version allowlist.

Once presentation completes, the UI thread sets native HWND focus and synchronizes WPF keyboard/logical focus. Preview.26 removes simulated Alt/Ctrl from focus retries; bounded retries also cover missing search focus, with another focus request after content rendering. Windows may refuse foreground permission. The program does not change foreground-lock policy or attach other threads' input queues. Toggling uses actual native foreground ownership rather than the WPF Topmost flag. Opening dimensions use logical window size, minimum dimensions, DPI scaling, and physical work-area clamping rather than a possibly minimized native rectangle. Logs include display-call duration and dimensions without typed text. Standalone Win cancellation and explicit native-menu requests still use marked SendInput; this change does not remove all synthetic input.

ShellIcon attached properties immediately show an embedded placeholder. Two background STA workers perform Shell/shortcut extraction through ShellIconConverter; pending requests and cached tasks are limited to 256. Duplicate paths share work; failed reads keep the placeholder. Frozen results return through the image's dispatcher and recheck its target before assignment, so recycled controls cannot display an earlier item's icon. A slow Shell extension can still occupy a worker, but cannot block layout or start unbounded workers. My Computer uses the same path.

`--reliability-test <directory>` checks blocked icon reads, dispatcher progress, queue bounds, async image assignment, shared discovery, placement, and snapshot recovery without showing windows or installing hooks. `scripts/Test-MenuWindow.ps1` runs window cycles and core regressions on a new inactive desktop, never calls SwitchDesktop, and closes the desktop after its child exits. Its child refuses to run on the input desktop. This does not test real Start interception or live search focus. `--probe-menu <directory>` reads only iStart window metadata in the current session, without titles, contents, activation, or input.

### Input thread and taskbar recovery

InputHookThread installs and removes low-level keyboard/mouse hooks in a dedicated STA message loop. Callbacks recognize gestures, validate local HWNDs, and dispatch UI work. Pending open requests are coalesced. Lifecycle generations reject work queued before a disable/re-enable cycle.

If the UI heartbeat is older than two seconds, keyboard input passes through and the Win gesture is cleared. Subsequent mouse-down events are not intercepted; an already-intercepted mouse-up is still consumed so Explorer does not receive half a gesture. Windows 10 StartTarget records the actual ButtonWindow and rechecks its class, parent taskbar, visibility, and current bounds on click. UIAutomation snapshots retain a 1.5-second freshness limit.

TaskbarCreated, WM_DISPLAYCHANGE, and WM_SETTINGCHANGE clear snapshots. Snapshot generations reject discovery results from before the change. A COM timeout tries native-window enumeration without accumulating blocked automation tasks. Enable requests share one pending task; bounded retries that still fail leave native Start available.

AdapterRecoveryTest supplies fixed builds 26200 and 26300 for cancellation/coalescing fixtures so a host OS update cannot short-circuit the intended wait. A build-26300 fixture with no buttons verifies detection failure without installing hooks; a build-26400 fixture verifies unknown-version rejection before scanning. Production callers always use the actual OS version. Startup diagnostics include the build alongside the stored preference, helping distinguish version rejection from a slow menu request.

### Screenshots

ScreenshotHotkey registers a global combination with RegisterHotKey/MOD_NOREPEAT after the main HWND is created. HwndSource routes WM_HOTKEY to capture. Normal shutdown unregisters the hotkey and removes its hook independently of Start integration. A missing ScreenshotShortcut defaults to Alt+Shift+A; unknown values are not registered. WeCom configuration is neither read nor modified. Conflicts keep the menu button available and are shown in Settings, with alternative combinations or Off. Interactive acceptance mode does not register global hotkeys; pure UI tests do not install global hooks.

MainWindow.Screenshot hides the menu and waits for repaint. Screenshot uses GDI CopyFromScreen for the selected monitor's physical pixels. ScreenshotWindow / CaptureSurface provide region movement/resizing and a floating annotation toolbar. Start cannot reopen the menu while editing. Export crops the original pixels and annotations and excludes the mask, selection border, and toolbar. Text and strokes remain in local memory; mosaic uses block sampling. Only Copy or Save outputs an image. PNG encoding completes before a temporary file replaces the destination; temporary files are cleaned. Capture is local and never enters activity history. Single-monitor capture is supported; real desktop hiding, clipboard behavior, and different DPI settings still require interactive acceptance.

### Appearance and test environment

Appearance supplies Windows/Google tokens through DynamicResource. MainWindow keeps the same navigation, search, and entry controls while ApplyThemeLayout moves navigation above the content for Windows or to its left for Google. UniformGrid uses six/five columns and stays aligned to the top. Windows has a flat neutral surface, four-DIP controls, and a full-width system bar; Google has capsule navigation/search, a 24-DIP content card, and round actions. MenuIcons.xaml composes existing WPF buttons with exact Figma-exported SVG alpha masks rasterized as embedded PNGs by the maintenance-only Prepare-MenuIcons.cjs; no runtime SVG library or network asset is required. App/file icons stay dynamic Shell data. Icon actions have translated tooltips, accessible names, focus indicators, and retained handlers. Healthy hints move to the section-title tooltip; empty states, errors, and operation feedback remain visible. The native titlebar/border/shadow remain, including the OS's outer-window geometry; no custom layered window or Mica is added. Settings saves the theme without restarting integration or changing privacy/startup preferences. Inputs retain PART_ContentHost. See [current theme checks](docs/THEME_VALIDATION.md).

`scripts/Test-WindowsVm.ps1` is a test-environment tool outside the product runtime. It invokes existing probes/regressions/input tests only in an identified Windows 10 x64 VM, isolating configuration and reports by run. The host may run read-only preflight; actual input/focus/recovery tests belong in the VM. VirtualBox, VM images/disks, account credentials, and local reports are not distributed with iStart or committed to the repository.

## Local storage and localization

`%LOCALAPPDATA%\iStart\library.json` uses schemaVersion 2 and migrates schema 1. Unknown versions are rejected. Invalid JSON may fall back to `.bak`; an unknown newer schema is not silently replaced with an older backup.

- Entries: id, target, title, categoryId; array order retains manual ordering.
- Categories: id and name; legacy order and the undeletable uncategorized identity are retained for compatibility, although category-editing UI was removed.
- Launches: target, title, openedAt, count; at most 100 unique targets; a record means launch was successfully handed to Windows.
- Preferences cover hidden apps, history reads, frequent/recent ordering, integration, startup, screenshot shortcut, icon view, and Theme. Windows/Google are valid themes; missing or unknown values fall back to Google.
- AutomaticUpdates: boolean in schema 2, default true for new and older configurations. Settings saves this preference immediately; manual mode still checks and notifies.
- Language: `System`, `zh-CN`, or `en`, within schema 2. Missing, empty, or unknown values become System. GetUserDefaultUILanguage reads the current user's display language; Chinese maps to Simplified Chinese, other unsupported languages to English. Windows language and regional formatting are not changed.

Language changes first persist through LibraryStore, then update bindings, navigation, search results, and system content. The existing Settings controls and unsaved checkboxes are retained. StartMenuAdapter and screenshot registration are not restarted; item names, privacy, and startup are unchanged. Shortcut labels are separate from stored identifiers; navigation icons use fixed GUIDs. The seven Control Panel labels are translated by category ID; volume labels retain user text. Shell names, native dialogs, the Chinese installer, and GitHub release notes retain their own language. See [Localization](docs/LOCALIZATION.md).

Data remains local. Removing an item never deletes its source. Legacy category operations retain migration/recovery support; deleting a category through the storage layer moves its items to the uncategorized identity. Store-app discovery supplements traditional shortcuts; apps without a valid Shell entry are not guaranteed to appear. Current app ordering and source limits are described in [Activity views](docs/ACTIVITY_VIEWS.md).

## Start integration and recovery

StartMenuAdapter runs one background taskbar scan and caches StartButton bounds. Callbacks check events and geometry and dispatch UI work; they do not read configuration or scan synchronously. Mouse validation includes the root window, live taskbar bounds, and snapshot freshness. Empty results or discovery exceptions update retry status without withdrawing the user's preference or disabling keyboard hooks. Old snapshots still require freshness and window validation; stale clicks pass through. Successful scans restore button interception. A timed-out pending scan is not repeatedly duplicated.

Standalone Win release suppresses native Start and shows iStart; Win combinations pass through. Marked temporary-native injection prevents recursion. Enable writes `session.active`; normal exit removes it. An ordinary launch with a leftover marker releases integration, saves native mode, and explains recovery. An explicit `--enable-menu` request takes priority over that marker; a separate enable signal forwards the request to an existing instance instead of merely showing it. On accepted session ending, integration and its marker are released before Windows can terminate the process, retaining the user's custom/native preference. A cancelled session-ending request leaves integration intact. Windows removes process-owned hooks at exit. Native recovery after terminating a separate test child has been checked.

Windows can remove low-level hooks after callback timeouts; reliable detection of every such removal is not yet established. Explorer restarts, multi-monitor/auto-hide/scaling, lock, and sleep recovery still need isolated acceptance. A build allowlist is not a complete compatibility guarantee. See [Microsoft's low-level keyboard hook guidance](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc).

Closing normally cancels window closure and hides the menu in the background without a notification-area icon. Shortcuts/taskbar launches and integrated Start entry points reopen it; Settings can disable integration. Explicit RequestExit from the menu or upgrade/uninstall signal, or system session ending, allows exit. RuntimeLog records lifecycle/adapter state, rotates at about 64 KiB, retains one old log, and does not record keystrokes or file paths. See [Resident recovery](docs/RESIDENT_VALIDATION.md).

## Account and power actions

Policies are read from current-user/computer policy keys; sleep/hibernate query system capability. Unsupported actions are hidden. Shutdown/restart use fixed `/t 0` arguments without `/f`; session-changing actions require product confirmation. Parameter construction and capability queries are tested. Disruptive actions have not been exercised in the daily work session, so complete account/power acceptance is not claimed.

## Installation lifecycle and packaging

The Chinese wizard covers welcome, location, options, actual file progress, and completion. Installation is per user without elevation. Desktop shortcuts, startup, and integration are off by default and opt-in. Installation success is distinct from Start-integration success: capability checks run in the real user process and failures keep native Start.

preview.23 uses `SatelliteResourceLanguages=en;zh-Hans`: English neutral framework resources, Simplified Chinese satellites, and embedded product English translations. PDB symbols stay in development output. The full self-contained WPF/WinForms runtime, COM, regional formatting, and recovery remain intact; unsupported WPF trimming and manual framework-DLL removal are not used. `lzma2/ultra64` solid compression needs an approximately 64 MiB decompression dictionary during installation. Publish-Preview checks the absolute output path is inside repository artifacts and is not a reparse-point directory before cleaning only `preview-win-x64`. CI runs the actual published EXE before isolated installation checks. See [Package size](docs/PACKAGE_SIZE.md).

Before upgrade or uninstall, the installer calls its own `--exit` and waits for the current user's instance to release the mutex. A timeout stops installation with an explanation instead of killing a process. Uninstall removes installed program files and the startup entry but keeps personal items. QA uses a separate AppId and skips real exit/startup operations so it does not close the daily installation.

Inno supplies cancellation, error, and rollback mechanisms, but disk-full, permission-denied, locked-file, and interrupted-upgrade cases still need hardware validation. Arbitrary upgrade failures are not guaranteed to restore every old file. Code signing is not implemented; commercial distribution must meet Inno and bundled .NET licensing requirements.

## My Computer and in-app updates

ComputerItems uses DriveInfo for partitions and capacity of ready local disks. Mapped network drives are listed without remote capacity queries. A current-user Shell.Application enumeration reads at most 16 Control Panel category-root entries and keeps seven category IDs: System and Security, Network and Internet, Hardware and Sound, Programs, User Accounts, Appearance and Personalization, and Clock and Region. Ease of Access and All Control Panel Items are excluded. COM objects are released in finally.

MainWindow.Computer reads asynchronously with a five-second waiting budget and does not duplicate an unfinished task. Compact three-column disks, Recycle Bin, Network, and expanded Control Panel entries support name search. System items open through one explorer.exe ArgumentList argument, do not enter personal file history, and do not empty Recycle Bin or perform other management operations. ShellIconConverter uses PIDLs for virtual-entry icons.

UpdateService belongs to MainWindow and owns the shared release/download/install state. Only installed non-test copies start its one-minute timer and network-availability subscription. A successful check waits six hours; failed checks/downloads wait fifteen minutes. Reconnection can request a check after a two-minute minimum interval. Network availability is a hint; a bounded HTTP request determines whether GitHub is reachable. Concurrent checks/downloads share a task. Disposal cancels work, removes the subscription, and rejects late results. GitHubUpdater reads only the fixed public Releases API: at most 100 releases, 2 MiB response, and a 30-second budget. Numeric version/channel selection, draft exclusion, exact x64 asset name and repository URL, size below 256 MiB, and GitHub SHA256 remain enforced.

Downloads have a fifteen-minute budget, actual byte progress, and a `.part` file in a unique GUID directory. Size and SHA256 must match before renaming to EXE. In manual mode closing the update page cancels its download; in automatic mode it continues in the background. Disabling automatic mode cancels a background download but retains the release notification. Failures clean the current temporary download. Successful-download cleanup only removes known updater-owned caches older than seven days, outside the latest two; unknown contents are retained.

UpdateWindow reads the shared state and shows current AssemblyInformationalVersion without its SHA suffix, target version, release body, and progress/results. Notes are limited to 12,000 characters and exclude the known release-provenance footer. MainWindow and Settings show red dots and accessible text while a newer release exists; opening the page does not dismiss the reminder. Automatic installation requires AutomaticUpdates, a hidden menu, no owned dialog or screenshot capture, no exit/session-ending request, and at least sixty seconds since the current session last received input. GetLastInputInfo supplies elapsed idle time without collecting keystrokes. The conditions are checked again after a second size/SHA256 verification. Manual installation needs an explicit click. Both launch the fixed downloaded installer with the current directory, merged startup task preference, /NORESTART and /NOCLOSEAPPLICATIONS. Automatic mode additionally uses /SILENT (progress visible), /SP-, and /AUTOMATICUPDATE=1; successful production installation starts the new app with --background, honoring its existing native/custom-menu preference. A completed installer that left the app running can be retried, with a fifteen-minute automatic backoff. Only installed copies with unins000.exe can execute an update. The configuration location/schema remain unchanged; there is no account token or activity upload. TLS/hashes do not replace publisher signing.

SmokeTest.Updater and SmokeTest.AutomaticUpdates use isolated HTTP/state fixtures for version channels, sources, download integrity, cancellation, offline/manual/automatic behavior, shared requests, idle gating, late-result rejection, install-time tampering, installer arguments, badges, current/target versions, and localized Windows/Google rendering. No fixture installer is executed. QA checks first install, overwrite with automatic-update arguments, and uninstall under a separate AppId. Full upgrades between public versions, production relaunch, interactive cancellation, and abnormal installation recovery remain separate acceptance work. See [Updates](docs/UPDATES.md) and [historical My Computer checks](docs/COMPUTER_UPDATE_VALIDATION.md).

## Compatibility trials

ShellCompatibility separates permission to try from hardware acceptance. Known Windows 10 19041–19045 and Windows 11 22000/22621/22631/26100/26200/26300 require explicit opt-in. Unknown builds are rejected. Even an allowed build must discover a valid button before installing keyboard/mouse hooks.

Windows 10 and 11 prefer visible native Start children belonging to the taskbar root, with a UIAutomation StartButton/Button fallback when no valid native child exists. Native candidates are revalidated at click time; UI Automation candidates retain a 1.5-second freshness limit. Taskbars fail independently. All candidates require finite coordinates, valid sizes, and taskbar bounds; detection does not depend on a localized Start name or guessed screen corners. Combination passthrough, native access, and abnormal-exit recovery remain unchanged. The current build-26300 read-only probe still uses UI Automation because no qualifying native Start child was found.

ShellProbe shares one asynchronous scan with a three-second wait. A timeout does not accumulate blocked scans. Settings can save a read-only report with app/OS versions, trial policy, monitor/button counts, methods, and geometry. It excludes usernames, file/browsing history, and full logs and is not uploaded. `--probe-shell` uses the same reader.

Tests cover known/unknown build policy, negative coordinates, invalid geometry, an off-screen nonactivating native Start fixture owned by the test process, hidden/out-of-bounds exclusion, recovery, and layouts. Current Windows 11 build 26200 input checks cover Win, Start, Win+R, temporary native mode, disable, and abnormal termination of a separate child. Windows 10 branches/fixtures are not Windows 10 system acceptance. Other builds, multi-monitor scaling, and Explorer restarts remain pending. See [Windows compatibility](docs/WINDOWS_COMPATIBILITY.md).

## Validation and publishing

SmokeTest checks persistence protection, migration, ordering, discovery filtering, recent records, and WPF list/icon rendering. InputIntegrationTest is an interactive-desktop specialist test, including native baseline, Win/button/combinations, temporary native mode, disable, and child-process recovery. Test-Installer only accepts the QA identity and new directories inside artifacts, checking silent first install, overwrite, and uninstall.

Windows CI retains core results, layouts, checksums, and installation results for seven days. It does not automatically publish a stable release. Complete Windows 10/other Windows 11, multi-monitor, and installation-failure matrices remain prerequisites for full release acceptance. See the [execution plan](EXECUTION_PLAN.md) and [current-system record](docs/CURRENT_SYSTEM_VALIDATION.md); outstanding manual inputs and session-disruption cases must remain explicit.

build.yml binds ProductVersion to the checkout SHA. release.yml takes the latest main SHA, a successful push/main run, and an authorization note, downloading only the installer allowlist. Publish-GitHubRelease.ps1 checks version, source workflow, and hashes, creates a draft, publishes it, and downloads the public files again. release-manifest.json records exact provenance and actual protection state. Releases are serialized with minimal GitHub Token permissions, no server, and no new production secret. Conversation authorization was used for recorded releases without claiming enforced GitHub approval. See [GitHub release procedure](docs/GITHUB_RELEASE.md).

## Historical implementation notes

These describe earlier previews. Current activity views supersede the old recommendation/category UI.

- **Store discovery:** read-only Shell.Application / AppsFolder enumeration retains IDs containing `!`. COM objects are released per item, with cancellation and a five-second budget. Traditional and store apps form the search candidates. Store entries launch via one explorer.exe ArgumentList argument and are not treated as disk files. Early recommendations were limited to 12; current My Apps uses the limits in Activity views.
- **Store icons:** SHParseDisplayName resolves AppsFolder to a PIDL; SHGetFileInfo with SHGFI_PIDL/SHGFI_ICON extracts the icon into a frozen bitmap. The 256-item cache is retained, with HICON/PIDL cleanup in finally. Failures use a generic EXE icon.
- **Windows recent files:** RecentDocuments reads up to 200 newest current-user Recent `.lnk` files with a five-second wait. It resolves targets and shortcut-modification times, filters network/missing/folder/EXE/LNK targets, deduplicates, and merges with Launches to 100 files. External history stays in memory; ShowWindowsRecentDocuments independently controls reading/display and discards late results when disabled. Shortcut times are approximate ordering evidence.
- **Cross-app history, preview.10:** JumpListDocuments reads the latest 60 AutomaticDestinations structured-storage files: at most 16 MiB each, 200 streams, and 1 MiB per stream. IPersistStream loads embedded Shell Link targets without Resolve or execution. IStorage/enumerator/IStream are released in finally. Stream/container modification times are approximate; DestList versions and CustomDestinations are not parsed.
- **LibreOffice:** read-only `4/user/registrymodifications.xcu`, at most 8 MiB, with XML DTD/external resolution disabled. Only PickList/OrderList/HistoryItemRef file URIs are used. Sequence order is preserved; configuration modification time is approximate.
- **WPS:** only HKCU/Software/Kingsoft/Office/6.0/{wps,et,wpp,pdf,ofd}/RecentFiles/files, up to 100 numbered subkeys' path values. No account/device/cloud records. Unknown open times remain unknown rather than fabricated; source sequence is preserved.
- **History safety:** sources fail independently. Network, missing, directory, executable, and script targets are excluded from documents. The merged limit is 100. Disabling external reads clears caches and rejects late results. Only configuration/link metadata is read, not document contents; external software/system history is not modified.
- **Recommendation display, preview.11:** new RecommendationsEnabled defaulted false; the entire SoftwarePanel collapsed without space. Settings was the only enable path. Search results remained independent. This UI and preference use were superseded by preview.16.
- **Mixed-item separator, preview.12:** EntryGroups classified apps through Shell IDs, executables/scripts, and shortcut targets, with a bounded cache. In unsearched All Favorites, a ListCollectionView grouped programs above files/folders, drawing a line only for the second group. Source Entries were not rewritten. Single-kind, category, recent, and search views did not add a separator. The mixed view was later replaced.
- **Windows 11 Fluent, preview.13:** Appearance added theme-specific spacing, search borders, button text, fonts, icon size, and status resources. Windows tiles became 64 DIP, typically six columns with container margins; smaller windows wrap. Google values were retained. CategoryIconConverter loads frozen navigation PNGs; search/account use embedded resources. SVGs remain maintenance sources, with no SVG renderer or network dependency. PART_ContentHost and focus/integration behavior were preserved.
- **Window rendering:** standard Windows titlebar, border, and shadow remain; the light layers do not enable native Mica. Figma supplied Noto Sans SC, while Windows uses Segoe UI Variable with Microsoft YaHei UI fallback. Google keeps its prior font. Runtime names and content are real, not mockup sample replacements.
- **Brand, preview.14:** Assets/Brand contains Figma SVG, transparent PNG, and nine-size ICO. Both themes use the PNG; the window uses the embedded ICO; ApplicationIcon embeds it in the EXE. The installer uses the same ICO and installs an independent file for shortcuts/uninstall. SVG conversion is maintenance-only. See [Brand icon](docs/BRAND_ICON.md).
- **Files/folders, preview.15:** RecentDocuments.Files filters before merging. FrequentFolders reuses ShellShortcut and JumpListDocuments directory mode, asynchronously refreshing file/folder caches within the existing five-second work. Added directories retain order; activity/time suggestions fill space. Suggestions and session hides stay in memory; pinning persists an item. The external-history switch clears both caches without a schema change. See [Recent files/folders](docs/RECENT_FILES_FOLDERS.md).
- **Activity views, preview.16:** MySoftware matches cumulative AppSwitched/iStart activity, at most 30 apps. SoftwareDiscovery adds EXE/AppUserModel.ID metadata. Four fixed views replaced recommendations/categories while Entries/Categories remained compatible. FrequentFolders adds direct-folder recent ordering without rewriting storage. WebsiteHistory reads bounded Chrome/Edge snapshots using system winsqlite3; MainWindow.Websites handles refresh and same-page ordering. Preferences persist, external suggestions/history stay in memory, and snapshots are cleaned in finally. No new NuGet or runtime-network dependency was added. My Computer later became the fifth view.
